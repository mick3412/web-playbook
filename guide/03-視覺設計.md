# 3 視覺設計

把線框變成有個性、但清楚好讀的畫面。

**這一步要產出：** 設計稿或可預覽的頁面

## 要做

- [ ] **3.1 版面**：滿版優先，留白要有目的；手機寬度先想
  - 幾種做法：(a) frontend-design 技能；(b) design-taste-frontend 技能
  - 版面的 7 條網格原則（S3-05，待試）
  - 改 AI 感介面：先列跡象、判斷輕重、寫方向等同意，再依九輪順序改（S3-07，待試）
- [ ] **3.2 影像與插圖**：真實照片和清楚的圖示優先於線稿插圖；照片先轉正再檢查比例
  - 檢查：照片先轉正，再檢查比例（S3-02）
  - 用真實照片和清楚的圖示，不用線稿插圖撐版面（S3-03）
- [ ] **3.3 動效**：動效有目的、短、可關閉（尊重 reduced motion）
  - 幾種做法：(a) Motion Design 技能定時間和緩動；(b) GSAP（時間軸、捲動）；(c) Three.js（真的需要 3D 時）；(d) 質感互動清單（S37）；(e) WebGL 特效一頁一個（S40）
  - 網站動效的三條底線（S3-01，待試）
  - 網頁 3D：用材質而不是面數做寫實，一頁只放一個 WebGL 重點（S3-06，待試）
- [ ] **3.4 深色與淺色**：兩種模式都設計、都檢查對比

## 用什麼工具

- **Three.js**（T-10）：頁面真的需要 3D 時
- **GSAP**（T-11）：網頁動效需要時間軸、捲動觸發、文字拆分時
- **Taste Skill（design-taste-frontend）**（T-12）：要避免 AI 味的版面和視覺時
- **unslop**（T-29）：畫面一看就是 AI 做的、要改版或上線前審查視覺時
- **GSAP AI Skills（官方）**（T-30）：用 GSAP 做時間軸、捲動觸發、文字拆分、SVG 變形等網頁動效時
- **emilkowalski/skills（emil-design-eng 等）**（T-36）：做或檢查網頁動畫時

**這一步可以試的新工具：**
- Motion Design 技能（LottieFiles）（T-14，待試）：要設計動效的時間、緩動、編排時；複查條件：下一支走到 3.3 動效 的作品
  - 測試方法：何時：設計網頁動效時間和緩動｜怎麼做：同一段動效裝技能前後各做一次｜看什麼：修改次數｜有效＝少一半
- ScrollCraft（T-17，未採用）：要做捲動驅動的網站時；複查條件：確認原文指的 repo 時
- WebGL 特效（ShaderGradient、Liquid Logo、Liquid Glass JS、React Three Fiber）（T-20，待試）：首屏需要一個動態重點時；複查條件：下一支走到 3.3 動效 的作品
  - 測試方法：何時：首屏需要動態重點｜怎麼做：做一個 WebGL 效果｜看什麼：效能分數、手機表現｜有效＝手機順暢且分數不掉
- Hallmark（T-22，待試）：建新頁、改版既有頁、或只想檢查 AI 感時；複查條件：做下一個網站時
  - 測試方法：何時：建新頁或改版｜怎麼做：用它做一頁或檢查一頁｜看什麼：是否一次問齊素材、多寬度檢查、AI 感｜有效＝產出不用大改
- PulsoIcon（T-26，待試）：按鈕、連結、分頁要有輕微的滑過動態圖示時；複查條件：做下一個網站時
  - 測試方法：何時：按鈕或連結要滑過動態圖示｜怎麼做：放 3 個圖示到頁面｜看什麼：效能、一致性｜有效＝輕量且風格一致
- Claude Code Skill 設計風格圖鑑（Casper）（T-27，待試）：挑風格或動效方向時先看成品；寫風格規格時拿它的 SKILL.md 當範本；複查條件：下一次要挑網站風格方向時
  - 測試方法：何時：下一次要挑網站風格（2.1）｜怎麼做：先看圖鑑挑 2–3 個方向，照 S2-02 寫規格｜看什麼：挑方向花多久、規格是否寫得出具體數值｜有效＝半小時內定出方向，規格每項都有數值
- Originkit（T-32，待查）：找現成的網頁動畫元件時；複查條件：2026-12-10；官網寫明元件授權時
- AI Particle Simulator（casberry）（T-33，待查）：要做粒子背景或片頭粒子效果時；複查條件：2026-12-10；官網寫明價格與授權時
- Impeccable（T-34，待試）：要給 agent 一組固定的設計指令（polish、bolder、critique、audit、抓 AI 感）時；複查條件：下一次介面改版時
  - 測試方法：何時：下一次介面改版｜怎麼做：同一個畫面用 Impeccable 和 unslop 各改一次｜看什麼：負責人偏好、修改次數｜有效＝明顯比 unslop 好才留
- Motion（原 Framer Motion）（T-40，待試）：CSS 做不到的動效：拖曳、版面切換、跟著捲動的複雜效果；複查條件：下一次遇到 CSS 做不到的動效時
  - 測試方法：何時：遇到 CSS 做不到的動效｜怎麼做：用 Motion 做，量打包大小和掉幀｜看什麼：效果、JS 增加多少、手機是否掉幀｜有效＝效果達成且不掉幀
- 動畫元件庫（Motion Primitives、Magic UI、Uiverse）（T-41，待試）：想找現成的動畫元件或小互動（按鈕、載入、切換）時；複查條件：下一次做 3.3 動效時
  - 測試方法：何時：下一次做 3.3｜怎麼做：挑 1 個元件改成自己的風格｜看什麼：是否符合 S3-01、S5-07｜有效＝留在成品裡且過檢查
- Anime.js（T-42，待試）：不用 React、要輕量的時間軸動畫時；複查條件：下一次做非 React 頁面的動效時
  - 測試方法：何時：非 React 頁面要做動效｜怎麼做：用它做一個時間軸動畫｜看什麼：程式量、檔案大小｜有效＝比手寫 CSS 少且順
- 插圖與 3D 圖示（Open Peeps、3dicons、unDraw）（T-44，未採用）：照片表達不了、需要插圖或 3D 圖示時；複查條件：照片表達不了的區塊出現時
  - 測試方法：何時：照片表達不了的區塊｜怎麼做：挑一套統一風格使用｜看什麼：是否和整站一致、是否顯得像模板｜有效＝留在成品且被評為不突兀
- Spline（T-45，待查）：想在網頁放可互動的 3D 場景時；複查條件：2026-12-10 或需要 3D 重點時
  - 測試方法：何時：真的需要 3D 重點時｜怎麼做：先確認免費方案條款再做一個場景｜看什麼：載入時間、是否帶浮水印｜有效＝免費可商用且不拖慢首屏
