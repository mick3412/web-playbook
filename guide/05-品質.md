  - 檢查：重建後分四層比：像素、SSIM 分區、系統量測差、新代理兩輪評審；最多 3 輪（S5-10）

  - 檢查：上線前的通用感關卡：先寫設計契約，看實際成品，只給 PASS 或 HOLD（S5-06，待試）

## 用什麼工具

- **Web Design Guidelines（Vercel）**（T-13）：審查介面是否符合規範時
- **unslop**（T-29）：畫面一看就是 AI 做的、要改版或上線前審查視覺時
- **Impeccable**（T-34）：上線前或改版後自動掃 AI 感與品質問題（npx impeccable detect <網址或資料夾>，62 條規則、不用 API 金鑰）；也有一組設計指令（polish、critique、audit）
- **Modern Web Guidance**（T-48）：寫元件、表單、動效或想把舊寫法換成瀏覽器內建功能時。寫介面前用 `npx modern-web-guidance search "<需求>"` 查標準做法（負責人允許後實跑：回傳 10 個相關做法，含無障礙與退路）

**這一步可以試的新工具：**
- Playwright CLI（Microsoft）（T-07，待試）：要批次截圖、查選擇器、錄測試時（Puppeteer 是同類工具，不另收）；複查條件：下一支走到 5.3 跨裝置 的作品
  - 測試方法：何時：要批次截圖或測試｜怎麼做：用它截多寬度整頁｜看什麼：速度、穩定性｜有效＝一個指令完成所有寬度
- Hallmark（T-22，待試）：建新頁、改版既有頁、或只想檢查 AI 感時；複查條件：做下一個網站時
  - 測試方法：何時：建新頁或改版｜怎麼做：用它做一頁或檢查一頁｜看什麼：是否一次問齊素材、多寬度檢查、AI 感｜有效＝產出不用大改
- agency-agents（網站挑 3 個）（T-28，待試）：上線前要獨立審查：通用感、無障礙、受眾模擬；複查條件：有網站要上線時
  - 測試方法：何時：上線前要獨立審查｜怎麼做：把 3 個角色檔放進專案各審一次｜看什麼：找出的問題是否中肯｜有效＝至少一個自己沒發現的問題
- agent-browser（Vercel Labs）（T-49，待試）：要讓 agent 實際開頁面、填表單、多寬度截圖檢查時；和 Playwright CLI（T-07）比；複查條件：瀏覽器自動化比較組 W6 測試時
  - 測試方法：何時：桌上試驗｜怎麼做：同一頁用它和 Playwright 各做 320／768／1440 三寬截圖與表單送出｜看什麼：指令數、耗時、截圖是否完整｜有效＝步驟更少且結果一樣
- WebAIM Contrast Checker（T-67，待試）：檢查文字與背景的對比是否達 WCAG AA／AAA 時；複查條件：下一次無障礙檢查
  - 測試方法：何時：下一次無障礙檢查｜怎麼做：在作品裡實際用一次｜看什麼：所有文字色組合是否通過 AA｜有效＝主要文字色組合全部通過 AA
- uSpec（create-voice）（T-75，待查）：交接前要寫螢幕閱讀器規格時；複查條件：下一次有表單或結帳流程的作品
  - 測試方法：何時：下一次無障礙交接｜怎麼做：在作品裡實際用一次｜看什麼：產出的 ARIA 是否正確、用螢幕閱讀器實測是否念得對｜有效＝螢幕閱讀器實測與規格一致
- axe-core（Deque）（T-79，待試）：上線前自動檢查無障礙問題時（可接 Playwright 每次跑）；複查條件：每次上線前
  - 測試方法：何時：每次上線前｜怎麼做：對主要頁面手機寬度跑 wcag2a／wcag2aa｜看什麼：violations 數｜有效＝嚴重以上歸零
