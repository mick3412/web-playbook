# 2 設計方向

定好風格和規則，後面每一頁都照同一套。

**這一步要產出：** 設計系統與線框

## 要做

- [ ] **2.1 參考與風格**：由大到小找參考，建一張參考表：L1 整體（整站風格、氛圍、色調）→ L2 結構（頁面版面、網格、區塊順序）→ L3 部位（每個要做的區塊分開找：開場、服務、常見問題、頁尾…）→ L4 細節（按鈕、卡片、導覽、字級、間距、微互動、動效）。每層 2–3 個參考；每列寫層、部位、參考（連結或截圖）、借的點、我們的數值。L3、L4 要涵蓋這次會用到的每個部位。
  - 幾種做法：(a) better-design 的靈感與設計系統工具；(b) extract-style 從網址擷取風格；(c) Design DNA 把參考轉成規格；(d) 參考圖庫（Land-book、Supahero 等）截圖給 AI；(e) 參考表範本與免費來源見 S2-04
  - 給 AI 2–3 張參考截圖，只借結構、網格和字體，不抄文字（S2-01，待試）
  - 由大到小找參考：整體 → 結構 → 部位 → 細節，再把借的點換成數值（S2-04）
  - 風格規格寫成固定八段，放具體數值（S2-02，待試）
  - 比較多種風格時，內容固定只換風格，用腳本驗內容沒被改（S2-03，待試）
  - 先判斷這一頁的模式，再決定設計要多大膽（S2-05，待試）
- [ ] **2.2 設計系統**：色（含深色模式）、字、間距、圓角、元件、圖示庫；寫成 tokens；每個數值標出來自參考表哪一列，或寫「自訂」和原因
  - 幾種做法：(a) design:design-system 技能；(b) better-design:create-design-system；(c) design-taste-frontend 技能；(d) 拿 Awesome DESIGN.md 當範本；(e) logo-design-skill 做 Logo
- [ ] **2.3 線框**：主要頁面的線框；核准後才做視覺

## 用什麼工具

- **better-design MCP**（T-04）：建設計系統、找圖示庫、審查版面和間距時

**這一步可以試的新工具：**
- REA（Reverse Engineer Anything）（T-05，待試）：想知道別人網站的某個互動或效果怎麼做時；複查條件：下一次要分析一個可以合法分析的軟體或網站時
  - 測試方法：何時：下一次想知道某個工具怎麼做出某效果｜怎麼做：setup 時逐項看要改的設定，只核准必要的；分析一個允許分析的對象｜看什麼：產出的說明是否正確、改了哪些設定｜有效＝得到可用的做法說明，且設定可以完整還原
- Awesome DESIGN.md（VoltAgent）（T-06，待試）：要定設計系統、想看好的 DESIGN.md 怎麼寫時；複查條件：下一支走到 2.2 設計系統 的作品
  - 測試方法：何時：定設計系統｜怎麼做：挑一份 DESIGN.md 當範本寫自己的｜看什麼：寫完是否涵蓋 token、元件、規則｜有效＝不用補就能交給 agent 用
- Design DNA（zanwei）（T-09，待試）：有參考介面、想把風格量化成規格時；複查條件：下一支走到 2.1 參考與風格 的作品
  - 測試方法：何時：有參考介面要量化｜怎麼做：把一個參考轉成規格｜看什麼：規格數值是否準｜有效＝照規格做出來跟參考感覺接近
- 網站設計參考圖庫（Land-book、Supahero、Pricing Pages、Social Proof Examples、Navbar Gallery、OG Image Gallery、Deck Gallery、Httpster、Mobbin）（T-15，待試）：找版面參考時。原 T-18 的靈感網站清單已併入這裡；複查條件：下一支走到 2.1 參考與風格 的作品
  - 測試方法：何時：找版面參考｜怎麼做：在圖庫找 3 個同類參考｜看什麼：花的時間、是否用得上｜有效＝10 分鐘內找到
- logo-design-skill（kaankiziltug）（T-16，待試）：要做或改 Logo 時；複查條件：下一支走到 2.2 設計系統 的作品
  - 測試方法：何時：要做或改 Logo｜怎麼做：用它出 3 個方向｜看什麼：負責人是否選得出一個｜有效＝一輪選出
- Claude Code Skill 設計風格圖鑑（Casper）（T-27，待試）：挑風格或動效方向時先看成品；寫風格規格時拿它的 SKILL.md 當範本；複查條件：下一次要挑網站風格方向時
  - 測試方法：何時：下一次要挑網站風格（2.1）｜怎麼做：先看圖鑑挑 2–3 個方向，照 S2-02 寫規格｜看什麼：挑方向花多久、規格是否寫得出具體數值｜有效＝半小時內定出方向，規格每項都有數值
- ui-ux-pro-max（T-37，待試）：選配色、字型、版型方向時；複查條件：下一次做 2.1 參考與風格時
  - 測試方法：何時：下一次做 2.1｜怎麼做：同一份需求分別問 ui-ux-pro-max 和 taste-skill 要方向｜看什麼：建議是否貼合產業、是否避開 AI 感｜有效＝它給出 taste-skill 沒有、而且被採用的建議才留
- design-mobile-apps（Sleek）（T-50，待查）：要快速出手機 App 畫面草稿時；技能本身 MIT，但實際呼叫付費服務 Sleek，要帳號和 API 金鑰；複查條件：確認 Sleek 有沒有免費額度，且負責人願意建帳號時
