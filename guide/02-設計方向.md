# 2 設計方向

定好風格和規則，後面每一頁都照同一套。

**這一步要產出：** 設計系統與線框

## 要做

- [ ] **2.0 方向對齊**：【決策窗 C 方向】開設計系統前，先用看得到的樣本對整站氣質，不只靠文字：挑 3–5 個參考站各跑 `pb.py teardown <網址> --no-tools` → `pb.py direction --web page <拆解資料夾…> --need "需求"` 出本機頁面（不發佈）→ 負責人做二選一（亮暗、留白、標題與內文反差、色彩收斂或繽紛、動態多寡，每題取參考站的兩極）、在參考牆標要或不要並勾要的是哪一點 → 下載 picks.json → `pb.py direction --web tiles picks.json --headline … --sub … --cta …` 用我們的文案做 3 個首屏 style tile → 負責人選一個 → `pb.py direction --web choose picks.json N` 寫出方向卡 direction.json 與 DESIGN.seed.md，2.2 從它開始寫 DESIGN.md
  - 幾種做法：(a) 參考站被機器人驗證擋下時 teardown 會標「被擋」並退出，不繞過；換一個參考或請負責人自己截圖；(b) 參考站 5 個以上，二選一比較能只差一個軸；3 個時頁面會標出還差在哪
  - 整站方向用看的決定：參考站量測的二選一＋參考牆＋3 個用我們文案做的首屏 style tile（S2-15）
- [ ] **2.1 參考與風格**：由大到小找參考，建一張參考表：L1 整體（整站風格、氛圍、色調）→ L2 結構（頁面版面、網格、區塊順序）→ L3 部位（每個要做的區塊分開找：開場、服務、常見問題、頁尾…）→ L4 細節（按鈕、卡片、導覽、字級、間距、微互動、動效）。每層 2–3 個參考；每列寫層、部位、參考（連結或截圖）、借的點、我們的數值。L3、L4 要涵蓋這次會用到的每個部位。。有參考網站時先跑 `pb.py teardown <網址>`：截圖、量測（間距級距、字級階、留白、色彩面積、特效、動態）、工具輸出都放進同一個資料夾，參考表的「借的點」和「我們的數值」從這裡取
  - 幾種做法：(a) better-design 的靈感與設計系統工具；(b) Design DNA 把參考轉成規格；(c) 參考圖庫（Land-book、Supahero 等）截圖給 AI；(d) 參考表範本與免費來源見 S2-04；(e) `pb.py teardown` 拆解參考網站（S2-10；節奏量測 S2-11）；(f) better-design 的 extract-from-url（只要 token 時）
  - 給 AI 2–3 張參考截圖，只借結構、網格和字體，不抄文字（S2-01，待試）
  - 由大到小找參考：整體 → 結構 → 部位 → 細節，再把借的點換成數值（S2-04）
  - 參考網站用一個指令拆成證據、量測和工具輸出，再由主模型寫成 DESIGN.md（S2-10）
  - 風格規格寫成固定八段，放具體數值（S2-02，待試）
  - 比較多種風格時，內容固定只換風格，用腳本驗內容沒被改（S2-03，待試）
  - 先判斷這一頁的模式，再決定設計要多大膽（S2-05，待試）
- [ ] **2.2 設計系統**：色（含深色模式）、字、間距、圓角、元件、圖示庫；寫成 tokens；每個數值標出來自參考表哪一列，或寫「自訂」和原因；拆解過參考站的，寫成 DESIGN.md（Google 規格，每個值標量／工具／目測），`npx -y @google/design.md lint DESIGN.md` 要過
  - 幾種做法：(a) design:design-system 技能；(b) better-design:create-design-system；(c) design-taste-frontend 技能；(d) 拿 Awesome DESIGN.md 當範本；(e) logo-design-skill 做 Logo；(f) 要做 Logo：配方 R-05 Logo 與品牌識別（名字先定→發想→向量→小尺寸與單色測試→規範）；(g) DESIGN.md 寫法與檢查見 S2-12
  - 風格合約寫成 Google 規格的 DESIGN.md，每個值標出處（量／工具／目測），lint 要過（S2-12）
  - Logo 五步：名字先定、發想方向、做成向量、測小尺寸與單色、寫使用規範（S2-06，待試）
  - 間距只用 4／8 的級距，外層容器比內層多（S2-08，待試）
- [ ] **2.3 線框**：主要頁面的線框；核准後才做視覺。送決策窗 D 前先跑兩輪新代理審查：`pb.py review-pack --stage web-wire --stills 線框截圖… --files DESIGN.md`。【決策窗 D 系統與線框】同一次給負責人：設計系統 style tile 頁（色票、字級階、按鈕、卡片、深淺並排）、線框、web-wire 兩份報告，以及參考表每列的「借、不借、改成我們的值」

## 要注意

- 免費版不可商用、套版範本做的 logo 不能註冊商標，只拿來發想（S2-07，待試）
- 工具自動判的氛圍與風格類別不可靠，只當線索（S2-13）
- 只借結構、節奏與系統；文案、圖片、商標、字體檔都不帶走（S2-14）
